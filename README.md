# Заготовка приложения для серверов Гимназии Сколково

Минимальное приложение (FastAPI) с готовой сборкой и автодеплоем. Из него удобно
начинать свой проект: создайте репозиторий кнопкой **Use this template**, замените
код в `app/` на свой и отправьте изменения в `main` — приложение соберётся и
обновится на сервере само.

Пример работает на **https://demo.technocrew.ru**.

## Как это устроено

```
push в main ──► GitHub Actions ──► образ ghcr.io/<владелец>/<репозиторий>:latest
                      │
                      └──► Coolify (devops.skolhub.ru): «задеплой приложение <UUID>»
                                   │
                                   └──► сервер skl-web-dev скачивает :latest и перезапускает
                                        контейнер; сайт открывается на <имя>.technocrew.ru
```

| Файл | Зачем |
|---|---|
| `app/` | код приложения и `Dockerfile` (слушает порт 8000) |
| `docker-compose.yaml` | запуск у себя на компьютере со сборкой из исходников |
| `docker-compose.prod.yaml` | запуск на сервере из готового образа — его читает Coolify |
| `.github/workflows/build.yaml` | сборка образа, публикация в GHCR и запуск деплоя |
| `.env.example` | список переменных окружения приложения (сами значения задаются в Coolify) |

## Запуск у себя

```bash
docker compose up -d --build
```

Приложение откроется на http://localhost:8000, проверка — http://localhost:8000/ping.

## Свой проект из заготовки

### 1. Репозиторий

1. На странице этого репозитория нажмите **Use this template → Create a new repository**.
2. В `docker-compose.prod.yaml` замените `aleksioprime/demo-app-coolify` в адресе образа
   на `<ваш-логин>/<ваш-репозиторий>` (строчными буквами).
3. Отправьте изменения в `main`. Workflow соберёт образ и опубликует его в GHCR;
   шаг деплоя пропустится, пока не заданы секреты Coolify — это нормально.

### 2. Сделать образ публичным

Сервер скачивает образ без пароля, поэтому пакет должен быть публичным:
GitHub → ваш профиль → **Packages** → пакет с именем репозитория → **Package settings**
→ **Danger Zone** → **Change visibility** → **Public**.

### 3. Попросить администратора создать приложение

Напишите администратору и пришлите:

- адрес репозитория и ветку (обычно `main`);
- желаемый адрес сайта: `<имя>.technocrew.ru`;
- порт, на котором слушает приложение (в заготовке — `8000`);
- какие переменные окружения нужны (имена из `.env.example`; значения передайте отдельно, не в общем чате).

В ответ вы получите **UUID приложения** и **токен Coolify** с правом только на деплой.

### 4. Секреты репозитория

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Значение |
|---|---|
| `COOLIFY_API` | `https://devops.skolhub.ru/api/v1` |
| `COOLIFY_APP` | UUID приложения от администратора |
| `COOLIFY_TOKEN` | токен от администратора |

### 5. Проверка

Отправьте любое изменение в `main` (или запустите workflow вручную во вкладке **Actions**).
В журнале шага «Trigger Coolify deploy» должно быть `deployment queued`, через минуту-две
сайт откроется по выданному адресу.

## Если что-то не работает

| Признак | Причина |
|---|---|
| Сборка падает на `Log in to GHCR` или `push` | в **Settings → Actions → General → Workflow permissions** выберите *Read and write permissions* |
| Деплой в Coolify падает с `unauthorized` при скачивании образа | пакет в GHCR не публичный (шаг 2) или в `docker-compose.prod.yaml` чужой адрес образа |
| Шаг деплоя пишет `401` или `Unauthenticated` | неверный `COOLIFY_TOKEN` или токен отозван — спросите администратора |
| Сайт показывает «Технические работы» | приложение не запущено или не слушает указанный порт; журнал контейнера есть у администратора в Coolify |

## Для администратора

Приложение создаётся в Coolify `devops.skolhub.ru` (корневая команда, сервер `skl-web-dev`):

1. Projects → New project `<Имя>` → окружение `production` → Add Resource → **Public Repository**
   (для приватного — Private Repository with Deploy Key).
2. Repository URL, ветка `main`, Build Pack **Docker Compose**, Base Directory `/`,
   Docker Compose Location `/docker-compose.prod.yaml`, сервер `skl-web-dev`.
3. Домен сервиса `app`: `https://<имя>.technocrew.ru:8000` (число после двоеточия — порт
   контейнера, наружу сайт открывается на 443). Запись DNS не нужна: `*.technocrew.ru`
   уже ведёт на `skl-web-dev`.
4. Переменные окружения из `.env.example` студента → Deploy.
5. Keys & Tokens → API Tokens → токен **только с правом `deploy`**, отдельный на каждого
   студента; отозвать, когда проект больше не нужен. Токен действует на всю команду,
   поэтому права `write` студентам не выдавать. UUID приложения — в его адресе в панели.
